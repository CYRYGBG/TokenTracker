## 顺序与验收

1. **统计正确性**：摘取上游 `0258ac0b` 的 Codex 会话/账本一致性修复；保持 fork 采集优化。验证分叉、旧 total-only、重置、复制去重、缓存升级、两次采集与源删保史。修订可读源记录并随整行 upsert 同步，已无源历史保留，不能伪造重算。
2. **本地存储写入**：独立 fork 模块实现有界增量日志与周期压实，优先用于大型长期会话与导出历史；旧 JSON 是可读基线，缺失键不删除。写入有锁、完整记录校验和、原子压实与中断恢复；备份/恢复/读取所有入口适配，不能仅优化写端。对未改变的数据不重写。用合成大数据测量字节量，不用 dirty-memory 估算 SSD 写入。
3. **真实同步增量**：seg 只发送相对上次成功发布状态变化的整行；base 保持全量，旧客户端仍能读取 fork_sync:1。上传失败不推进基线，重装/远端领先强制恢复后 base；验证向下修订、源删保史、混合旧全量 seg/新增量 seg、多段丢失、故障重试、双设备幂等与压实。
4. **复用读取与报表计算**：按文件身份/大小/纳秒时间失效共享快照和在途请求；去掉个人版路径重复同步读 queue；设备用量一次加载后分组；周/月报用同一快照生成所需结果或复用接口计算，避免六条独立路径反复解析。测试缓存更新/替换/并发、偏好/价格变化、设备范围、日期/时区与错误语义。
5. **低价值唤醒与凭证读取**：文字额度没有图标消费者时暂停动画；保留额度刷新与实际采集。状态接口仅查询凭证存在性并适当缓存，保存/清除/账号地址变更立即失效，Windows 不为每次状态查询启动 PowerShell；不将明文密码额外持久化。验证显示切换及失败/变更。
6. **恢复与更新可靠性**：失败重试独立于正常同步间隔，遵守 Retry-After/指数退避/认证暂停，全部触发器仍互斥；释放错误响应正文。Mac 更新复用上游限流判定/冷却/网页回退思路，严格限制个人版 tag/平台资产并继续 SHA256 校验；Windows 检查已有回退的一致性。测试虚拟时钟与 HTTP/重定向故障。
7. **回归、构建与交付**：Node 全量、dashboard Vitest/typecheck/validate/build、Swift 更新/原生逻辑、Windows 更新逻辑与打包运行时。隔离 HOME 冒烟，性能前后对比（标明范围），核对打包源码 SHA。构建 macOS arm64 DMG、Windows x64 Setup；上传两包及 SHA256SUMS，验证远端 digest/匿名下载/latest/旧版更新通道后发布。Windows 兼容环境不写成实机验收。提交计划、结果和公开安全证据。
