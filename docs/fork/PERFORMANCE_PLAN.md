# 常驻能耗与磁盘读写优化方案

2026-10-30 制定，2026-10-31 实施。1.4.20 已实现第 1–3 阶段的主要瓶颈修复：ZCode opt-in Node 只读与元数据 SQL/历史分界下推、Harness 文件身份缓存、历史工作线程/在途合并/跨进程锁与保存价格表传递。第 4 阶段保留为后续按实际瓶颈推进的检查项，不将尚未改动的路径写成已完成。同步请求延长至 180 秒的本地修复及发布状态单独见 STATUS.md。

## 已有证据与计量口径

- ZCode 旧 message 查询读取整段 data JSON 并按 time_created 排序，查询计划为全表扫描、临时 B-tree；常驻 serve 与本地采集子进程都捕获到相关读取。
- 原读取方式先调用 sqlite3 CLI，30 秒超时后再次用 Node SQLite 执行。同 SQL 在打包 Node 中直接读取为 1819/564 ms，19960 行、约 59.6 MB data，结果哈希一致。这里的 30 秒是本地 SQLite CLI 的时限，与 WebDAV 网络请求原来的 30 秒是两项独立配置。
- 系统磁盘诊断记录 file-backed memory dirtied 约 8.6 GB；这不是 SSD 实际写入量，也不是统计文件增长量。后续使用进程实际 I/O 计数、临时文件/统计文件写入、CPU 时间和物理内存分别验收，不能用这一项直接宣称减少多少 SSD 写入。
- DSH 未变化文件仍反复解压是次要开销。macOS 一分钟 serve 兜底与五分钟原生采集同时启用的假设已排除；不能通过随意关闭额度或同步来规避主因。

## 实施顺序

### 1. 先消除慢 CLI 失败后重读

- 在安装版支持的 Node SQLite 上为重型 ZCode 读取优先使用只读 Node 接口，避免全量 JSON 经子进程输出、再序列化/解析，以及 30 秒失败后再执行一次查询。
- 优先限制在独立适配模块或显式读取选项，避免未经回归就改变所有 provider 的 SQLite 默认行为。Node 20/缺少 node:sqlite 时保留 CLI；数据库锁定、损坏、权限错误不得当作空数据，也不得缓存失败。
- 不改变 SQL 选择集合、Token 归一化、消息去重、模型归属和定价。即使换读取器更快，serve 主线程仍可能被同步数据库调用阻塞，需要在第三步解决调度位置。
- 验收：同 SQL 的行数、统计字段哈希、Token/费用/会话合计一致；支持 Node SQLite 的成功路径不启动慢 CLI；测试 Node 20 不可用回退、锁定、失败和 Node 22 打包运行时。

### 2. 缩小旧格式查询与排序载荷

- 将旧格式兼容读取限制到真正需要保留的历史范围，先核对 native/legacy 分界、时间戳单位及缺失时间的既有规则；不能因为已有 model_usage 就直接删除旧消息来源。
- 查询只投影计算所需的计数、标识、时间、模型/厂商和有依据的分析字段，避免把完整正文 JSON 搬进临时排序文件或进程输出。保留结果顺序和去重依赖；不能直接去掉 ORDER BY 或给用户的源数据库加索引。
- 沿用上游解析与统计实现，由独立 fork 模块适配元数据输入，不重写统计引擎。
- 验收：原生/旧格式混合、历史空窗、重试、子代理、缓存/推理 Token、向下修订均一致；连续两次采集不重复；源日志删除后历史保留。

### 3. 合并扫描与复用未变化的会话

- 将后台历史收集、同步导出和会话页发起的相同元数据构建合并为一个在途任务；有更新才失效，同步导出尽量复用已持久化的结果。跨进程读取不能只靠一个进程内 Map 解决。
- DSH 使用文件身份、大小、修改时间和解析器版本复用已归一化的元数据，变化时才重新解压；保留截断、同大小替换、失败重试与压缩预算规则，不缓存原始正文。
- 重型历史构建放在有界采集子进程或 worker，服务主循环继续响应界面与状态请求；同时只允许运行一个构建任务，取消/退出时清理资源。
- 数据库缓存需正确识别 WAL 中的真实数据变化，不能仅为命中缓存而忽略 WAL，也要调查只读操作是否使 SHM 元数据变化造成无效失效。失败扫描不得替换上次完整快照。
- 验收：未变化的热缓存周期不解压旧文件、不执行旧消息整表查询；工具持续写入、改标题、数据库替换和休眠唤醒后仍能及时更新；已保存历史不依赖源文件存在。

### 4. 再减少无变化写入与无意义唤醒

- 在确认上述主因改善后，按实际 I/O 测量检查历史合并、导出 manifest 和快照：内容未变化则不重写；变化时尽量只处理变化部分。当前已有 hash/retain 去重应复用，不先大改存储格式。
- 检查只为显示状态而反复启动 security/解密凭证的路径，改成适当缓存或只查存在性，保存/清除凭证后立即失效；不扩大凭证存储范围。
- 检查文字菜单栏隐藏图标时的动画计时器、隐藏页面请求和原生定时器容差。关闭无消费者的装饰刷新，保留五小时额度、活动采集与用户指定的同步频率。

## 验收与交付边界

- 使用不含用户正文的合成大体量数据库夹具，并只读核对真实库的结果与进程指标；不复制、提交或上传原始对话数据库。
- 在相同输入与相同观察窗口比较冷启动、无变化空闲、持续使用、手动同步、自动同步、休眠恢复五类场景的查询次数、CPU 秒、实际读写字节和峰值物理内存。暂停重型构建/测试后再做能耗对照，避免把开发任务误计入应用效果。
- 首要通过条件是统计完全一致、无重复/漏计/丢历史、成功路径不再先等 30 秒 CLI 超时，以及无变化周期不再做历史整表查询。CPU/实际写入下降幅度以测量为准，不预先承诺百分比或 SSD 寿命收益。
- 代码回归通过后再构建并核验双平台；Windows 构建不能代替 Windows 实机测量。发布、安装与长期 72h 常驻观察分别记事实状态，不把本地修复写成已分发。
